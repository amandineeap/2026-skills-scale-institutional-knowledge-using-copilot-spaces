# Change Management Checklist

This checklist is used by the Change Manager to manage change requests from intake through implementation. Complete each section in order and document outcomes in the change log.

---

## 1. Change Request Intake and Documentation

- [ ] Change request received and assigned a unique ID (e.g., CR-001)
- [ ] Requestor name, date, and contact information recorded
- [ ] Description of the proposed change documented clearly
- [ ] Business justification or driver for the change noted
- [ ] Affected scope areas identified (features, timelines, budget, resources)
- [ ] Supporting materials attached (mockups, specs, emails, etc.)
- [ ] Change request status set to **Pending Review** in the change log

---

## 2. Impact Assessment

- [ ] Scope impact evaluated: does this change add, remove, or modify deliverables?
- [ ] Schedule impact evaluated: does this change affect any milestone or release date?
- [ ] Budget impact evaluated: are additional resources or costs required?
- [ ] Quality impact evaluated: does this change introduce risk to acceptance criteria or test coverage?
- [ ] Dependencies identified: does this change affect other teams, systems, or integrations?
- [ ] Risk level assigned: Low / Medium / High
- [ ] Impact assessment documented and shared with the Project Manager
- [ ] Relevant stakeholders notified of the pending change for input (if applicable)

---

## 3. Stakeholder Notification Workflow

- [ ] Change request and impact assessment shared with affected stakeholders
- [ ] Stakeholder feedback period defined (e.g., 3 business days)
- [ ] Feedback collected and recorded in the change log
- [ ] Change reviewed and approved/rejected by the authorized approver (Project Sponsor or Project Manager depending on impact level)
- [ ] Approval or rejection communicated to the requestor
- [ ] All stakeholders notified of the final decision and rationale
- [ ] Change log updated with decision outcome and date

---

## 4. Implementation and Rollback Procedures

- [ ] Approved change added to the project backlog with acceptance criteria
- [ ] Implementation tasks assigned to appropriate team members
- [ ] Updated timeline or milestone dates communicated to the project team
- [ ] Rollback plan documented: steps to revert if the change causes issues
- [ ] Rollback triggers defined: conditions under which rollback will be initiated
- [ ] Change implemented and tested according to acceptance criteria
- [ ] QA Lead confirms the change meets quality gates
- [ ] Change status updated to **Implemented** in the change log
- [ ] Post-implementation review scheduled (if change was High impact)
